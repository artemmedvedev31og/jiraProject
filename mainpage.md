# Genius Music Bot {#mainpage}

## Назначение проекта

**Genius Music Bot** — Telegram-бот на Java для поиска музыкальных треков по имени исполнителя с использованием Genius API. Пользователь запускает бота, выбирает поиск, вводит имя исполнителя и получает список найденных композиций. Для навигации используются команды и интерактивные кнопки Telegram.

Документация описывает архитектуру приложения и компоненты, относящиеся к задачам SCRUM-8, SCRUM-9, SCRUM-10, SCRUM-15 и SCRUM-16.

## Основной сценарий работы

1. Пользователь отправляет `/start` и получает главное меню.
2. Пользователь выбирает «Поиск» или отправляет `/search`.
3. Бот переходит в состояние ожидания имени исполнителя.
4. Введённое имя передаётся в `GeniusClient`.
5. Клиент формирует HTTP GET-запрос к Genius API и получает JSON-ответ.
6. Ответ преобразуется в набор моделей `GeniusResponse`, `Response`, `Hits` и `Result`.
7. Из ответа извлекаются названия треков, имена исполнителей и доступные ссылки. Выдача ограничивается пятью результатами API.
8. Бот форматирует результаты и отправляет их пользователю в Telegram.

Команда `/back` или действие «Назад» позволяет вернуться в главное меню.

## Компоненты проекта

### `MainMenu`

Координирует обработку входящих сообщений Telegram и переходы между пользовательскими состояниями. Метод `handleSearchMenu` обрабатывает введённый запрос и запускает поиск через `GeniusClient`.

### `GeniusClient`

Создаёт HTTP-клиент для обращений к Genius API, формирует запросы, передаёт токен авторизации, обрабатывает HTTP-ответ и преобразует JSON в Java-объекты. Методы `searchArtists` и `getUrls` возвращают соответственно список композиций, сгруппированных по исполнителям, и ссылки на найденные треки.

### Модели ответа Genius API

- `GeniusResponse` — корневой объект ответа, содержащий поле `response`.
- `Response` — содержит коллекцию `hits`.
- `Hits` — описывает один элемент выдачи и содержит объект `result`.
- `Result` — хранит название композиции, имя исполнителя и ссылку на страницу Genius.

### `UserData` и `UserState`

`UserData` хранит пользовательские данные и текущее состояние каждого чата в памяти приложения. `UserState` перечисляет состояния, используемые при навигации и взаимодействии с найденными треками.

## Задачи

### SCRUM-8. Ввод имени исполнителя и запуск поиска

Обработка пользовательского ввода в `MainMenu`, передача поискового запроса в API-клиент и возврат результата в сценарий Telegram-бота.

### SCRUM-9. HTTP-клиент Genius API

Создание HTTP-клиента, формирование GET-запроса к endpoint поиска, кодирование строки запроса и передача заголовка авторизации.

### SCRUM-10. Обработка JSON-ответа и модели данных

Преобразование структуры ответа API в Java-модели с полями для имени исполнителя, названия трека и URL.

### SCRUM-15. Сетевые ошибки и время ожидания

Обработка проблем при обращении к API и настройка тайм-аута установления соединения. В текущей реализации `HttpClient` задаёт `connectTimeout` в 12 секунд; это ограничивает время установления соединения и само по себе не является отдельным тайм-аутом полного HTTP-запроса.

### SCRUM-16. Подготовка и ограничение списка результатов

Подготовка данных для вывода в Telegram и ограничение количества обрабатываемых результатов первыми пятью элементами ответа Genius API.

## Конфигурация и безопасность

Токены Telegram и Genius API читаются через классы `ParserKeys` и `Keys` из конфигурации приложения (`keys.json`). Реальные токены не следует включать в исходный код, документацию, коммиты или публичные архивы. Для запуска необходимо предоставить корректный конфигурационный файл в ресурсах приложения.
